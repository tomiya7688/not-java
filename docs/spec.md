# Not java — 言語仕様メモ

> Java の真反対を走る。ただし、実用性は捨てない。

この文書は設計会話からの記録です。**決定した方針**と**未決定・構文が仮の部分**を分けます。実装と一致するとは限りません。

## 1. 基本思想（決定）

- クラスは存在しない。
- 変数の明示的な宣言構文は存在しない。名前を使うと変数が生まれる。
- 値そのものに型はない。データの格納形式には区別があり、事実上の型として働く。
- 関数も変数として扱える。関数を変数へコピーして使い、使い終われば解放する。
- 代入は参照共有ではなく、内容のコピー。
- ガベージコレクタはない。変数の寿命は原則として自分で管理する。
- 名前空間・import・using の代わりに、相対ファイルパスとメンバー参照をドットでつなぐ。

## 2. 変数、null、free（決定）

- 名前を初めて参照した時点で、その名前の変数が暗黙に作られる。
- 値未設定の変数を読むと `null` が返る。
- `null` の**値を格納するためのデータ領域**は 0 バイト。ただし変数自体は存在し、メモリ上の番地を持つ。
- 数値の `0` と `null` は異なる。`0` はデータを格納する。
- 同じ変数への再代入は、その変数の内容を置き換える。旧値を別変数として残さない。
- `free(a)` は変数 `a` を解放し、その名前は未使用状態に戻る。
- `free(a)` 後に `a` を再び読むと、新しく作られて `null` が返る。
- 2 回目の `free(a)` でも、存在しない `a` が生成されて解放されるので二重解放エラーにはしない。
- `a = null` は値がない状態への変更であり、`free(a)` のように変数自体を消す操作とは異なる。

概念例（表記は暫定）：

```text
print(a)   // null：初回参照で生まれる
a = 255    // 1バイトの数値データ
a = 256    // 2バイトに拡張
a = 1      // 1バイトに縮小
a = null   // 値データは0バイト、変数は存在
free(a)    // 変数を解放
print(a)   // 新しいaが生まれ、null
free(a)    // エラーではない
```

### 2.1 コピー代入（決定）

```text
a = `Hello`
b = a
free(a)
print(b)  // bは独立したコピーなので残る
```

メモリの拡張で実際のデータ格納番地が移動するかどうかは実装詳細。**変数としての同一性**と**物理番地の固定**は別問題。

## 3. データ表現と演算（決定）

- 数値と文字列ではメモリへの格納方法が異なる。
- **文字列の基本エンコーディングは UTF-8**。文字列はUTF-8で符号化されたバイト列を保持する（文字数とバイト数は一致しない場合がある）。
- **数値は普通の数値として演算し、必要なバイト数だけ使って自動伸縮**する。整数だけでなく小数にも適用し、整数幅や小数精度を固定しない。
- バイト列が同じであれば、文字列と数値でも `==` は一致しうる。ただし比較時に相互変換はしない。
- 値に型タグを付けて型検査するのではない。
- 二項演算の**左辺の格納形式**によって、命令を実行する時に演算方式を決める。
- 右辺を便利な形に暗黙変換しない。格納されているデータをそのまま演算に使う。
- したがって `` 5 + `5` `` と `` `5` + 5 `` は別の演算になる。

例（文字列はUTF-8。数値の具体的なバイト表現と混合演算規則は一部未決定）：

```text
5 + `5`  // 左辺が数値表現 -> 数値的な加算
`5` + 5  // 左辺が文字列表現 -> 文字列的な加算。5を文字「5」に変換しない
```

### 3.1 自動伸縮メモリ（決定）

- 数値は必要な最小サイズから始める。値データの最小単位は 1 バイト（8 bit）。
- 演算結果が表現範囲を超えたら、1 バイトずつ自動的に拡張する。
- 値が小さくなった場合も、不要なデータ領域を自動的に縮小する。
- 文字列など、データ長が変わる値も必要な分に合わせて伸縮する。
- 有限桁の小数は、表現と計算に必要な分だけ領域を増減させる。
- データ領域の**サイズ変更**は自動だが、変数自体の**解放**は手動。

例（非負整数・リトルエンディアンを仮定した説明用の値）：

```text
255       -> 1 byte
256       -> 2 bytes
65536     -> 3 bytes
1         -> 1 byte
null      -> 0 bytes of value data
```

### 3.1.1 小数演算と循環への対処（方針決定）

- 小数も整数と同様、必要な桁数とデータ量に応じて自動拡張・縮小する。固定の小数点以下桁数は設けない。
- 有限小数については、表現できる範囲で余計な丸めを行わず正確な演算を目指す。
- 除算などで桁が続く場合、ある程度計算して**循環を検出し、循環開始位置に近い桁数で有限長に打ち切る**方針とする。
- 有理数の除算では、筆算の余りが再登場すれば循環を検出できる。循環開始位置と周期長は余りの履歴から得られる。
- ただし計算をどの桁数まで試すか、循環開始から何桁残すか、切り捨て/丸め、期限までに循環を発見できなかった場合の動作は未確定。有限小数でも極端に長ければ資源上限に達しうる。
- 分数ではない計算や無理数など、循環しない無限小数を生成しうる操作の打ち切り規則も未決定。

```text
0.1 + 0.2  // 0.3 （有限小数は余計な丸めをしない）
1 / 8      // 0.125 （有限小数）
1 / 3      // 0.3 など（循環は早めに打ち切る。表示桁数は未決定）
1 / 7      // 0.142857 など（周期をどこまで残すかは未決定）
```

※ 上の周期の桁数は**候補例**であり確定仕様ではない。数値の内部形式や演算規則は別途定義する。

**UTF-8格納例（決定）：**

```text
`A`   -> 41          // UTF-8で1バイト
`あ`  -> E3 81 82    // UTF-8で3バイト
```

※ 文字列エンコーディングはUTF-8、小数も自動伸縮させて循環時は有限長に打ち切る方針は確定。数値の符号表現、小数の内部形式、エンディアン、異種バイト列の算術規則は未決定。

### 3.2 条件分岐と真偽値（決定）

- 条件分岐は `If(条件) { 処理 }` を採用する。処理ブロックは `{}` で囲む。
- Booleanなどの真偽値型は定義しない。式のデータ表現をそのまま真偽判定に使う。
- **値のバイト列がすべて `0x00` なら偽、1バイトでも非ゼロなら真**。
- `null` は値データ0バイトなので偽とする。
- 等値比較 `A == B` は値の**バイト列そのもの**を比較する。格納方式の区分や型に相当する情報は比較に用いない。
- バイト長が等しく、対応するすべてのバイトが等しい場合のみ数値 `1`（真）を返し、それ以外は数値 `0`（偽）を返す。
- 0バイト同士の比較は一致するので `null == null` は `1`。0バイトの `null` と1バイト以上の `0` は一致しない。
- 数値と文字列であっても、データの生バイトが完全一致すれば等しい。比較のための暗黙的変換はない。
- 数値が等しい `A` と `B` に対して、`A - B` は `0` となり偽に判定される。条件に比較式以外の式を渡してよい。

```text
A = 10
B = 10

If(A == B) {
    print(`Equal`)  // 1 → true
}

If(A - B) {
    print(`Different`)  // 0 → false、実行されない
}
```

バイト列比較の例（文字列はUTF-8、数値は非負整数を最小バイト数で表すと仮定）：

```text
65 == `A`     // 1: 0x41 == 0x41
15 == `15`    // 0: 0x0F と 0x31 0x35
0 == null     // 0: 1 byte と 0 bytes
null == null  // 1: 空のバイト列同士
```

※ ここでの `true` / `false` は判定結果を説明する語であり、独立したBoolean型の存在を意味しない。文字列の基本文字コードはUTF-8で確定。数値の符号やバイト順序など詳細表現は未決定だが、**比較規則は生バイト列の長さと内容の一致**で確定。`Else` の詳細な文法も未決定。

## 4. 関数（決定）

- 関数には引数の型宣言がない。そもそも値に型がない。
- 関数は Function 相当の格納形式を持つ変数として扱う。「Function 型」は型検査上の型を意味しない。
- 通常は関数を別の変数へコピーして呼び出し、不要になった関数変数を `free` する。
- 元の関数定義はプログラム終了まで存在する。
- 関数の内部に static なメンバーを持たせ、関数をコピーすることで独立したデータのまとまりを作れる。
- 引数が不足した場合、渡されなかった引数名は `null` になる。
- 仮引数より多い個数を渡すことはエラー。

例（`fn` / `print` / `static` の表記は暫定）：

```text
fn hello() {
    print(`Hello`)
}

a = hello
a()
free(a)

b = hello
b()
free(b)
// 元のhelloはプログラム終了まで存在
```

引数の例：

```text
fn show(a, b, c) {
    print(a)
    print(b)
    print(c)
}

show(10)             // bとcはnull
show(10, 20, 30, 40) // ERROR: I can't receive it???
```

## 5. データのまとまりとメンバー（決定）

- 専用の class / struct 宣言は不要。
- `A = b, c, d` のように値をまとめられる。
- メンバーには `A.b` のようにドットでアクセスできる。
- static な `b`, `c`, `d` を持つ関数 `a` を作り、コピーして複数の独立したまとまりを得ることもできる。

```text
b = 15
c = `Hello`
d = 255
A = b, c, d
print(A.b)
```

※ メンバーの格納レイアウト、静的メンバーの正確な宣言構文、関数コピー時のコード本体の複製方法は未決定。

## 6. ファイルと名前解決（方針決定）

- `namespace`, `using`, `import` を必須としない。
- 相対パスとメンバーアクセスをともに `.` で表す。
- 同一ディレクトリの `sub.nj` 内の関数 `u` のメンバー `p` は、`sub.u.p` で参照する。
- ローカルに名前がある場合はそれを確認し、なければ相対ファイルパスを解決する方針。
- 単独の未知の名前は暗黙に `null` 変数となる一方、ドットで指定したメンバーが見つからなければエラー。

```text
// Ain.nj から参照
sub.u.p
```

※ ローカル名とファイル名が衝突するケース、ディレクトリ区切りの厳密な文法、循環参照の扱いは未決定。

## 7. エントリーポイントと処理系

**決定：** `main` などの固定名を特別扱いしない。

- エントリーポイントは**コンパイル時に任意で指定できる**。
- **指定しなかった場合は、コンパイル対象として指定したソースファイルを先頭から順に実行する。**
- エントリーポイント指定を必須にはしない。

例（構文は仮）：

```text
print(`First`)
print(`Second`)
// 指定なしで実行すると First → Second の順
```

### 7.1 トップレベルでの関数コピーと実行（決定した振る舞い）

エントリーポイント未指定時は、トップレベルに記述した関数定義、変数へのコピー、関数呼び出し、解放のような処理を順に実行できる。

```text
// 概念例：関数定義構文は仮。呼び出しは A() で十分
B() {
    print(`Hello`)
}
A = B
A()
free(A)
```

- 関数 `B` を定義し、変数 `A` にコピーして実行する。
- `A` の関数コピーは `free(A)` で解放できる。
- 元の `B` はプログラム終了まで存在する。
- 元の例 `B(){}` / `a=b` / `Execute A()` は、引数なしの関数呼び出しを `A()` と表せるので、専用の `Execute` キーワードは不要と考えられる（`A()` を呼び出し構文の候補とする）。
- パーサーは `B() { ... }` のように閉じ括弧の直後に関数本体 `{ ... }` が続くかを見て、単独の `A()` の呼び出しと区別できる。
- `A()` が呼び出し可能な関数データを持つかどうかは実行時に判定する。関数でなければ実行エラー。
- 正式な関数定義構文、名前の大文字小文字の扱い、エラーメッセージは引き続き未確定。

※ 明示的なエントリーポイントを指定した場合にトップレベル文も実行するか、関数定義をいつ初期化するか、複数ファイルの初期化順序は未決定。

**検討中：** JVM や独自 VM に依存しない、ネイティブ AOT コンパイルを主方式にする案。途中で純粋インタプリタ案も出たが、最終決定は保留。実行時に演算方式を選ぶことは AOT と両立できる。

※ コンパイラのコマンドライン表記・拡張子（会話内では `.nj` を使用）などは未確定。

## 9. 未決定事項（次に詰める）

1. **正式な字句・構文**：関数定義、文字列、コメント、代入、戻り値、static、呼び出し、`Else` の詳細。
2. **メモリ上の厳密な表現**：数値の符号・小数の内部形式・バイト順序、数値/文字列の区別の保持場所、0バイト変数の番地。文字列の基本エンコーディングはUTF-8で確定。
3. **演算規則**：バイト長の異なる左右の加算、`null + x`、演算結果の格納形式、小数の打ち切り上限・周期の保持桁数・丸め方。`==` の比較原則は生バイト列一致で確定。
4. **スコープと名前解決**：ローカル/ファイルの優先順位や衝突、パス解決、メンバーの可視性。
5. **関数の実装**：関数コピーと static の独立性、再帰、クロージャ、呼び出し規約。
6. **解放の境界**：ネストしたメンバーの `free`、関数から抜けたローカル変数の扱い、メモリ不足時。
7. **実装戦略**：AOT の最終決定、コンパイラ CLI、ビルド・実行可能ファイル形式。明示的エントリーポイント指定時のトップレベル実行規則も含む。
